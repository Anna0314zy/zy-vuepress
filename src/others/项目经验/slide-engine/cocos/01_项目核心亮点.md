# ICW Creator 项目核心亮点

## 1. 业务定位与价值主张

ICW Creator 定位为**交互式课件（Interactive Courseware）创作与交付一体化工程**：覆盖 Web 端编辑器、多端播放器、独立渲染进程、桌面云盘壳应用及素材转码等链路。其价值不在于「功能清单」，而在于将**课程数据结构（Schema）— 编辑态状态机 — 运行时渲染引擎 — 对象存储与转码服务**约束在同一套 Monorepo 契约之下，降低跨团队、跨-runtime 的集成成本。

## 2. 工程形态：pnpm Workspace Monorepo

仓库以 `pnpm-workspace.yaml` 统一纳入 `packages/*`、`apps/*`、`extensions/*`、`services/*`，根 `package.json` 暴露版本与发布语义（如 `standard-version`、私有 registry）。该形态的**原始动机**是：

- **依赖图单源化**：`@icw/schema`、`@icw/typing`、`@powercourse/player-sdk`、`@powercourse/render-engine-cocos2` 等以 workspace 协议引用，避免「npm 发包滞后」导致的契约漂移。
- **发布与构建工具内聚**：`@icw/release-tool` 支撑 Widget 构建与加载脚本（`load:app-deps`），将扩展资产与主应用构建流水线绑定。

## 3. 数据契约优先：Schema + 版本迁移

`@icw/schema` 将页面描述抽象为可校验结构（`async-validator` + descriptors），并提供 `updateToLatest` / `backToOldVersion` 的**版本区间归约**。这在架构评审语境下的含义是：**课件 DSL 被当作可演进的协议**，而非一次性 JSON；播放器、编辑器、云端转换必须能对齐同一版本语义，否则会出现静默兼容性问题。

## 4. 编辑端：Rematch + Immer + 中间件式持久化

编辑器采用 `@rematch/core` 配合 `@rematch/immer`，在 Redux 之上收敛「模型—副作用」边界；`realTimeSave` 中间件对 `main` 命名空间下的 action 做白名单拦截，在具备 `pageId` 时触发 `savePageJson`。该设计的**取舍**是：用「Action 级副作用」替代分散在组件内的保存调用，换取一致性；代价是**保存触发与业务 action 耦合**，需维护白名单与 payload 约定。

## 5. 运行时拆分：Player SDK、渲染引擎、教室桥接

- **Player V2**：依赖 `@powercourse/player-sdk`、`@classpod/classroom-bridge` 等，面向课堂场景的观测与控制能力（日志、桥接协议）。
- **渲染引擎包 `@powercourse/render-engine-cocos2`**：以 `tsup` 产出 CJS/ESM，依赖 `@powercourse/game-sdk` 与 `socket.io-client`，体现「游戏引擎宿主 + 实时通道」的组合，用于将课件运行时从纯 Web DOM 抽象到引擎层。
- **独立渲染应用**（`cocos-render`、`se-render`）：将不同后端引擎隔离为独立构建单元，避免编辑器 bundle 与重度 runtime 强行合并。

## 6. 云与 Serverless：`sl-conversion` 转码矩阵

`services/sl-conversion` 以 **esbuild 打 Bundle + 腾讯云 SCF（Serverless Cloud Function）** 部署，入口按资源类型分发至 `convertPPT` / `convertPPTPack` / `convertPDF` / `icwPack` 等 handler，并在失败路径串联 **业务回调通知（`notifyConversionResult`）与 Lark 告警**。亮点在于：**长耗时、环境依赖重的转换逻辑被移出浏览器主线程与编辑器进程**，以异步任务模型承接，符合课件导入/export 的峰值特征。

## 7. 桌面与 IDE 集成：`cloud-driver` 与 VS Code 插件

- **Cloud Driver**：引入 `@classpod/native-api`，承担原生窗口消息与云存储相关路由，将「桌面壳」与 Web 业务页解耦。
- **gameclient-vscode-plugin**：把创作链路延伸到 Cocos 工具链场景，体现**工具链插件化**而非单一 Web App。

## 8. 可观测性与稳定性基建

根依赖包含 `@sentry/react`、`@sentry/webpack-plugin` 等，指向**前端异常与性能追踪**在生产环境的刚性需求；Player 侧单独引入 `@sentry/browser`，符合多端部署时分仓配置的习惯。

## 9. 小结：评审视角下的「亮点一句话」

若以一条架构陈述概括：**ICW Creator 是以 Schema 契约为轴心、Monorepo 为边界、编辑器状态机与引擎运行时分离、Serverless 承接重计算的交互式课件平台工程**；其亮点集中在**契约演进能力**与**运行时/工具链拆分**，而非单一界面特性。
