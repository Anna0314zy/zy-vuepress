# ICW Creator 技术难点剖析

## 1. 课件 DSL 的版本演进与双向兼容

### 1.1 难点陈述

`@icw/schema` 同时承担 **校验**（`validate`）与 **纵向迁移**（`updateToLatest` / `backToOldVersion`）。难点不在于写出单个 `versions[x].updateOldVersion`，而在于：

- **迁移组合爆炸**：从任意旧版本到新版本需经过有序变换链；当前实现通过 `getVersionRanges` 切片与 `reduce` 串联完成归约。
- **不可逆信息损失**：升级路径若引入新必填字段，降级（`backToOldVersion`）必须定义语义丢失策略，否则播放器与编辑器会出现「静默截断」。
- **校验与迁移次序**：应先迁移再校验，或校验宽松模式兼容中间态；次序错误会导致合法历史数据被拒绝。

### 1.2 隐性工程成本

版本文件分散在 `packages/schema/src/versions/*.ts`，需要 **变更评审规范**：新增字段必须同时更新 descriptor、`typing` 与迁移函数，并在播放器侧做 **渐进发布**（旧播放器 + 新数据的风险）。

## 2. 编辑器侧：富交互状态与持久化的正交性

### 2.1 难点陈述

编辑器集成 Draft.js、Fabric、FFmpeg.wasm、音视频波形等，属于 **高副作用 UI**。Rematch 将业务状态收敛到 model，但「画布选中态、拖拽中间态、临时预览」往往不适合每次 action 都落盘。

### 2.2 中间件 `realTimeSave` 的边界

当前实现对 `main` 命名空间白名单化，并以 `payload.pageId` 作为保存触发条件。难点在于：

- **漏存**：若某关键变更走了非 `main` model 或未携带 `pageId`，会出现「界面已改但未持久化」。
- **频写**：未在中间件层看到 debounce；若 `savePageJson` 内部无合并策略，可能造成请求风暴。
- **一致性**：`store.getState()` 在中间件内读取的是 dispatch 前或后的状态取决于 Redux 中间件次序；需确认与 `next(action)` 的先后是否满足「保存的是新状态」这一预期（通常应在 `next` 之后读取）。

**评注**：若生产代码已在 `savePageJson` 内 debounce，则难点下沉到服务层；架构文档仍应标注该契约。

## 3. 多运行时下的渲染与资源路径解析

### 3.1 难点陈述

存在 Web 编辑器、Player、Cocos/SE 渲染应用及 VS Code 插件。资源 URL、相对路径、COS 签名、引擎内资源管理（`@huohua/cocos-asset-manager`）在不同 runtime 下语义不一致。

`player-sdk` 中出现 `resolvePath` 等工具模块，典型难点包括：

- **基路径（base URL）** 在 iframe、桌面 WebView、引擎静态目录之间切换。
- **缓存失效**：签名 URL 过期与播放器缓存策略冲突。
- **跨域与 COOP/COEP**：若未来引入 WASM 线程或 SharedArrayBuffer，需统一响应头策略。

## 4. Serverless 转码的可靠性与可运维性

### 4.1 难点陈述

`sl-conversion` 将 PPT/PDF/打包等逻辑打入单一 bundle，部署于 SCF。难点包括：

- **执行时限与内存**：大文件解压、逐页渲染易触碰平台上限；需分层拆分或异步 Step Functions 式编排（若腾讯云侧有等价方案）。
- **依赖原生二进制**：若 `resource-converter` 间接依赖系统库，Serverless 镜像与本地开发环境 drift。
- **幂等与重试**：`axios-retry` 仅覆盖 HTTP 客户端；业务层需 `taskUUID` 贯穿以避免重复入库。
- **观测**：云函数日志与业务任务 ID 的关联、Lark 告警风暴抑制。

## 5. 桌面壳与 Web 业务的消息边界

`cloud-driver` 依赖 `@classpod/native-api`，难点在于 **postMessage/原生桥** 的协议版本化：字段增删、超时语义、安全校验（origin、payload 签名）。若协议与 Web 路由深度耦合，会造成桌面端与浏览器端发布无法独立。

## 6. 构建链路与遗留栈的叠加

### 6.1 显性技术难点

- **Webpack 4 + react-scripts 4**：与现代 bundler（Rspack/Vite）相比，冷启动与缓存策略偏弱；维护补丁（`patch-package`）说明上游缺陷已在业务侧打补丁固化。
- **Node OpenSSL**：多处 `NODE_OPTIONS=...openssl-legacy-provider`，表明加密算法与现代 Node 默认策略冲突，属于 **环境绞杀点**，阻碍 CI 镜像升级。

### 6.2 依赖补丁

`dom-to-image`、`whatwg-fetch` 等 patch-package 说明 **渲染导出与 fetch polyfill** 在现有依赖版本上存在边界 bug；补丁文件需纳入审计与升级评估。

## 7. 小结

本项目的技术难点集中在 **「契约演进 × 多运行时 × 重计算外包」** 的交集：任何单一维度单独出现都属常规工程，三者叠加后，**排查路径长、复现成本高**，必须通过 Schema 版本治理、任务幂等、观测关联 ID 与渲染路径单测化逐个拆解。
