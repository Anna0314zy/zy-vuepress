# ICW Creator 性能优化方案

> 下列方案区分「已由当前架构隐含承载的能力」与「建议演进项」，并给出**可落地的实现要点**，避免泛泛「优化性能」表述。

## 1.  bundle 体积与加载路径

### 1.1 现状与瓶颈

编辑器 `apps/editor` 依赖面积极广（音视频、OCR、图形、Markdown/Math、React Flow 等），在 Webpack 4 默认拆分策略下，易出现 **首屏 vendor 过大**、**长效缓存命中率偏低**。

### 1.2 优化手段

1. **按路由与重型特性做 `React.lazy` + `Suspense` 切割**：将 OCR、FFmpeg、图形导出等非首屏路径延后加载；配合 webpack `magic comment` 命名 chunk 便于监控。
2. **构建分析门禁**：对 `@icw/editor` 产物运行 bundle analyzer，设定 **chunk 体积预算**（与 schema 包的 `size-limit` 思路对齐）。
3. **引擎与编辑器发布分离**：已通过独立 `cocos-render` / `se-render` 应用承载部分负载；进一步可将 `@powercourse/render-engine-cocos2` 在编辑器侧仅引入 **类型与序列化**，运行时通过 iframe/协议加载，降低主 bundle 常驻内存。

### 1.3 预期收益机制

减少 **解析与编译 JS 的主线程时间**，以及降低 **内存常驻对象数量**（尤其 FFmpeg WASM 与图形库）。

## 2. 状态更新与渲染频率

### 2.1 现状与瓶颈

Rematch + Immer 降低手写 immutable 成本，但若 model selector 粗放，仍会导致 **大范围 React re-render**。

### 2.2 优化手段

1. **细粒度 selector**：对画布高频更新区域使用 `reselect` 或拆分局部 Context，避免整页 connect。
2. **批量 dispatch**：将连续 micro-update 合并为单次 action（Rematch 支持或在 reducer 内聚合）。
3. **确认 `realTimeSave` 与渲染路径解耦**：持久化 IO 不得阻塞 reducer；若 `savePageJson` 同步触发网络，应确保异步且不反向 dispatch 高频 action。

## 3. 持久化与网络 I/O

### 3.1 现状与瓶颈

`realTimeSave` 在特定 action 上触发保存；若无 debounce，编辑高频操作（拖拽、输入）可能放大 **HTTP 请求次数**。

### 3.2 优化手段

1. **Debounced flush**：按 `pageId` 维度维护 timer，静默期（如 300–800ms）合并写入；销毁页面时 `flush`。
2. **差异同步**：若服务端支持 patch（JSON Patch / CRDT binary），将全量 `pageJson` 替换为增量，降低带宽与序列化成本。
3. **离线队列**：启用 Rematch persist 插件或与 Service Worker 结合，弱网时写入 IndexedDB 队列并 backoff 重试。

## 4. 媒体与画布

### 4.1 现状与瓶颈

波形（wavesurfer）、视频 Info、图像压缩（compressorjs）、DOM 转图片（dom-to-image）均属 **CPU/GPU 敏感路径**。

### 4.2 优化手段

1. **Web Worker**：波形解析、图片压缩、大 JSON 校验迁入 Worker；主线程仅负责调度与进度。
2. **降级策略**：低端设备关闭实时预览、降低采样率。
3. **导出路径**：优先 `<canvas>`/`OffscreenCanvas` 流水线，避免对大 DOM 树 `dom-to-image` 全量 rasterize（补丁说明该路径存在稳定性修补）。

## 5. Player 与运行时

### 5.1 现状与瓶颈

Player 依赖 COS 下载与 RPC；弱网下 **首帧时间** 与 **音频同步** 易受影响的概率高于编辑器。

### 5.2 优化手段

1. **资源预签名与 HTTP/2 多路复用**：合并小文件请求或使用 manifest 驱动并行下载上限。
2. **缓存分层**：内存 LRU + IndexedDB 持久化课件壳层资源；注意 COS 签名 TTL。
3. **引擎侧**：降低每帧 JS bridge 调用次数，批量更新节点属性（需 game-sdk 配合）。

## 6. Serverless 转码链路

### 6.1 现状与瓶颈

云函数冷启动、大包体、同步链路超时。

### 6.2 优化手段

1. **预留实例 / 最小实例数**：对高峰导入场景购买稳定性。
2. **异步化**：HTTP 入口立即返回 `taskId`，长步骤走队列；客户端轮询或 Webhook。
3. **分层拆分**：PPT/PDF/打包拆分函数，缩小单包体积，提升 **冷启动命中率**。

## 7. CI 与 Monorepo

1. **Affected 构建**：基于变更包计算仅构建 `apps/editor` 或 `player-v2`，缩短 PR 反馈。
2. **pnpm store 与缓存**：缓存 `pnpm-lock.yaml` 解析结果与构建产物哈希。

## 8. 优先级建议（评审用语）

| 优先级 | 项 | 理由 |
|--------|-----|------|
| P0 | 保存 debounce + flush | 直接影响服务端负载与编辑流畅度 |
| P1 | 编辑器重型依赖 lazy load | 首屏与迭代反馈最明显 |
| P2 | Player 资源缓存策略 | 课堂场景体验敏感 |
| P3 | Webpack → 现代 bundler 迁移 | 中长期工程效能，短周期风险高 |
