# 系统演进路线图

## 1. 演进原则

1. **契约优先**：任何特性先进 `@icw/schema` / `typing`，再进 UI。
2. **渐进替换**：避免「停写业务做大重写」；优先替换 **构建链路与高风险路径**。
3. **可观测闭环**：每个演进阶段必须有 **指标或告警** 验收。

## 2. 短期（1–3 个月）：稳定性与债务止血

| 事项 | 动作 | 验收 |
|------|------|------|
| 持久化竞态 | 审视 `realTimeSave` 与 `savePageJson`：`next` 次序、debounce、etag | 压测下无覆盖写 |
| 依赖安全 | 对齐 axios、openssl、webpack 相关 advisory | 扫描门禁通过 |
| patch 审计 | 建立补丁清单与移除条件 | 每项补丁关联 issue |
| CI affected | pnpm filter 构建受影响包 | PR 构建耗时下降 |

## 3. 中期（3–9 个月）：工程效能与运行时优化

| 事项 | 动作 | 验收 |
|------|------|------|
| 构建升级 | Webpack 5 / Rspack 或 Vite 迁移试点（优先 player-v2 或独立 SDK） | 冷启动与 HMR 改善量化 |
| 编辑器切割 lazy | 重型库路由级动态加载 | FCP/LCP 改善 |
| Player 缓存 | COS 签名刷新与多级缓存策略 | 弱网首帧指标改善 |
| Schema 测试 | 迁移与校验一体化测试矩阵 | 覆盖率与回归清单 |

## 4. 中长期（9–18 个月）：平台化与协作能力

| 事项 | 动作 | 验收 |
|------|------|------|
| 插件/widget 市场 | 强化 `release-tool` 与 sandbox API | 第三方 widget 接入文档与示例 |
| 协作编辑（可选） | 引入 op log / CRDT 选型验证 | PoC 冲突解决 UX |
| 多区域部署 | COS + SCF 多地域与 CDN 策略 | 跨区域延迟下降 |

## 5. 长期（18 个月+）：AI 原生与智能运维

参见 `07_AI原生转型路线图.md`：契约溯源、Command Bus、RAG、课堂遥测闭环、多 Agent 工作流。

## 6. 风险登记表（需在评审会上 owner）

| 风险 | 影响 | Owner（虚拟） | 缓解状态 |
|------|------|----------------|----------|
| Node/OpenSSL 策略收紧 | CI 与本地无法构建 | 基建 | legacy provider 过渡中 |
| React Router 版本分裂 | 共享路由组件困难 | 平台组 | 评估统一到 v6 |
| Socket.IO 版本锁定 | 安全与兼容 | 运行时组 | 服务端协议评估 |
| SCF 超时 | 大文件导入失败 | 后端 | 异步化改造 |

## 7. 结语

ICW Creator 的演进主线是：**先把契约与持久化做对**，再 **压缩构建与运行时成本**，最后 **平台化 + 智能化**。任何跳过第一阶段直接上大特性的路径，都会在多端与历史资产场景下付出 **指数级排障成本**。
