# 高频面试考题（含标准答案）

以下题目按大厂 **P7/P8** 系统设计与会话深度命题，标准答案均锚定 ICW Creator 仓储内的真实技术选型（Monorepo、Rematch、Schema 迁移、独立渲染应用、SCF 转码等），候选人既可答通用原理，也应能映射到本项目边界。

---

## Q1：你们的 Monorepo 边界如何划分？如何解决「改一处、全仓重建」的问题？

**标准答案：**

边界划分遵循 **交付单元与契约稳定性** 两层逻辑。交付单元上分为 `apps`（可独立部署的 SPA/插件壳）、`packages`（跨应用复用的 SDK、schema、引擎封装）、`services`（Node/Serverless 侧能力）、`extensions`（引擎或编辑器扩展资产）。契约稳定性上，将 `@icw/schema`、`@icw/typing` 作为 **协议层**，将 `@powercourse/player-sdk`、`@powercourse/render-engine-cocos2` 作为 **运行时适配层**，避免编辑器直接依赖引擎内部实现。

针对重建风暴，工程上通常组合：**pnpm workspace 的依赖去重**、**Affected 构建（按变更包计算 DAG）**、**远端缓存（build cache）**。评审要点不是「是否 Monorepo」，而是 **是否有包图分析与 CI 裁剪**；若尚未落地 affected pipeline，应诚实列为演进项并给出基于 `pnpm -r --filter ...` 或 Nx/Turbo 的迁移路径。

## Q2：课件 JSON 为什么要单独抽 `@icw/schema`？直接用 TypeScript 类型不够吗？

**标准答案：**

TypeScript 类型在编译期擦除，无法保障 **运行时数据** 合法；课件数据来自云端历史资产、导入工具、第三方剪辑链路，属于不可信输入。`async-validator` + descriptors 提供运行时校验，能在 **播放器解码前**、**编辑器载入后** 拦截非法结构，避免引擎内部空指针或静默渲染错误。

此外，本项目实现了 **版本迁移**（`updateToLatest` / `backToOldVersion`），这是 DSL 作为「协议」而非「DTO」的标志：类型只能描述某一版本形状，无法表达 **跨版本变换**；迁移函数与版本表是协议治理的一部分，必须与 TS 类型协同演进而非替代关系。

## Q3：编辑器状态管理为何选 Rematch，而不是 Redux Toolkit（RTK）或 Zustand？

**标准答案：**

Rematch 在 Redux 之上提供 **models 聚合 reducers 与 effects** 的默认约定，配合 `@rematch/immer` 可直接在 reducer 中写「可变写法」以降低样板代码。选型动机通常是：**团队已有 Redux 生态习惯**、需要 **可预测的 action 命名空间**、以及中间件（如 `realTimeSave`）与 Redux DevTools 兼容。

与 RTK 相比，Rematch 社区活跃度较弱，长期属于 **维护权衡**；与 Zustand 相比，Rematch 更侧重 **大型协作式状态的可追溯性**（action log）与中间件链。面试高分点是承认 **栈龄**：Rematch 在 React 17 + CRA 时代常见，若新项目启动可能优选 RTK Query + RTK；迁移策略可按模块渐进替换而非大爆炸。

## Q4：中间件 `realTimeSave` 如何实现「编辑自动保存」？有什么并发与一致性隐患？

**标准答案：**

实现机制是 Redux 中间件拦截 action：解析 `action.type` 的命名空间前缀，若属于白名单（当前为 `main`），则在 `payload.pageId` 存在时调用 `savePageJson(projectCode, pageId)`，最终 `next(action)` 继续派发。

隐患包括：（1）**保存时点**：若在 `next` 之前读取 `store.getState()`，持久化的可能是旧状态；规范做法是 `const result = next(action)` 后再读取状态或依赖 reducer 已完成提交。（2）**竞态**：快速连续操作可能导致后发先至的网络响应覆盖新内容，需要 **版本向量 / timestamp / etag**。（3）**部分保存**：仅 page 粒度若与跨页引用资源不一致，需要事务或资源快照策略。

## Q5：为何要把渲染拆成 `cocos-render`、`se-render` 独立应用，而不是编辑器内嵌？

**标准答案：**

核心动机是 **进程隔离与发布节律解耦**。游戏引擎运行时体积大、崩溃面宽、升级频繁；与 React 编辑器同进程集成会导致：bundle 巨大、热更新困难、引擎 bug 拖垮整个编辑会话。独立应用可通过 iframe 或原生窗口嵌入，编辑器仅保留 **消息协议与资源契约**。

代价是 **联调成本高**：需规范 postMessage/schema、统一调试开关与版本握手；收益是 **稳定性与团队并行**：引擎组与课件编辑组可独立发版。

## Q6：`services/sl-conversion` 放在 Serverless 上，你如何设计超时、重试与幂等？

**标准答案：**

云函数适合 **突发导入峰值**，但受 **超时与内存** 约束。设计要点：（1）入口快速返回 `taskId`，重步骤异步化，避免 HTTP 同步阻塞。（2）业务幂等键使用请求中的 `uuid` 或平台生成的 `context.request_id`，在存储层做 **唯一索引** 防止重复落地。（3）HTTP 客户端层可用 `axios-retry` 处理瞬时网络故障，但与业务幂等配合，避免 **重复副作用**。（4）失败路径需结构化错误码并入 `notifyConversionResult`，同时 **告警聚合**（本项目有 Lark 通知雏形）防止抖动刷屏。

## Q7：播放器侧引入 `@classpod/classroom-bridge` 与 `json-rpc-2.0`，架构上解决什么问题？

**标准答案：**

课堂播放器不仅是「渲染课件」，还需与 **教室宿主**（桌面客户端、Electron、专用浏览器壳）交互：举手、权限、设备、日志上报等。Bridge 提供 **宿主能力与播放器沙箱** 的边界；JSON-RPC 提供 **请求/响应语义**，比裸 postMessage 更易处理超时、错误传播与类型化封装。

架构评审关注的是：**RPC 方法表的版本治理**、**安全模型**（谁可调用 teacher-only 方法）、以及 **降级路径**（纯 Web 无宿主时的 stub）。

## Q8：依赖里同时出现 `semantic-release-monorepo` 与 `standard-version`，你怎么制定单一真相的版本策略？

**标准答案：**

二者都可生成 CHANGELOG 与版本 bump，但触发机制不同：`semantic-release` 偏 CI 驱动与自动化/npm 发布；`standard-version` 偏本地/流水线生成 conventional commit 版本。并存容易造成 **版本号来源冲突**。

治理方案：选定其一为主；（1）若包需要频繁独立发 npm，偏向 semantic-release + monorepo 插件；（2）若主要是私有部署且发版节奏人为控制，可保留 standard-version 并弱化自动化发布。关键是 **changelog、git tag、registry 三元一致**，并在文档写明触发条件。

## Q9：Webpack 4 + `openssl-legacy-provider` 说明什么？升级路径是什么？

**标准答案：**

说明构建链依赖的旧加密算法或工具链接口与 **Node 17+ OpenSSL 3 默认策略不兼容**，属于典型 **基建绞杀**。短期用 legacy provider 延缓；中期升级 webpack/sass-loader 等链条；长期迁移 **Webpack 5 / Rspack / Vite**，并在 CI 固定 LTS Node 与镜像。

升级需验证：dynamic import、`import.meta` polyfill（仓库已出现相关 babel 插件）、patch-package 补丁是否仍必要。

## Q10：如何测试 Schema 迁移的正确性？

**标准答案：**

分层测试：（1）**单元**：对每个 `versions[v].updateOldVersion` 构造最小 fixture，断言字段增减与默认值。（2）**性质测试（可选）**：对随机合法旧对象，验证 `backToOldVersion(updateToLatest(x), oldVer)` 在允许的信息损失约束下可预测。（3）**契约测试**：播放器与编辑器共用 golden files（真实历史课件快照）跑迁移 + validate。（4）**灰度**：新版本播放器兼容旧数据读取；新版本编辑器写入开启 feature flag。

高分点是强调 **「迁移函数与 descriptor 同事务变更」** 的评审门禁，否则易出现校验失败或运行时字段缺失。
