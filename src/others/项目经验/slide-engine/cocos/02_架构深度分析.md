# ICW Creator 架构深度分析

## 1. 分层与边界

### 1.1 表现层（Presentation）

| 单元 | 职责 | 架构含义 |
|------|------|----------|
| `apps/editor` | 课件编排、画布、组件属性、媒体处理 | 重交互 SPA，Ant Design + 大量媒体/图形依赖 |
| `apps/player-v2` | 课堂播放、与教室 SDK 协同 | 运行时瘦身后仍依赖 COS、RPC、事件总线 |
| `apps/cloud-driver` | 桌面壳内云能力路由 | 隔离原生 API 与 React 路由 |
| `apps/cocos-render` / `se-render` | 引擎侧渲染入口 | **进程/应用级隔离**，降低编辑器与引擎生命周期纠缠 |
| `apps/gameclient-vscode-plugin` | IDE 扩展 | 扩展交付形态，共享类型与协议 |

### 1.2 领域与状态层（Editor）

编辑器选用 **Rematch** 而非手写 Redux boilerplate，配合 **Immer** 降低不可变更新成本。Store 初始化显式命名 `cws-editor-store`，插件栈预留了 `persist`、`loading`（当前注释掉），说明团队曾评估**离线缓存与全局 Loading 语义**，现阶段收敛为更小内核。

**隐性复杂度**：Rematch model 粒度若与业务模块不一致，易出现「巨型 model」或 circular effect；需依赖代码评审约束拆分。

### 1.3 数据契约层

`@icw/schema` + `@icw/typing` 构成 **课件 DSL 的类型与校验双轨**：运行时校验捕获非法数据，版本迁移函数捕获历史资产。该层是播放器、编辑器、转换服务的**唯一真相来源（候选）**；若 typing 与 schema descriptor 漂移，会导致「编译通过但运行校验失败」类缺陷。

### 1.4 基础设施层

- **对象存储**：多处 `cos-js-sdk-v5` / `cos-nodejs-sdk-v5`，区分浏览器与 Node 运行时。
- **Serverless 转码**：`sl-conversion` 将 CPU/IO 密集逻辑托管到云函数，编辑器仅触发任务与轮询/回调。
- **实时通道**：渲染引擎包依赖 `socket.io-client`，暗示运行时存在 **引擎侧或服务侧推送**，用于进度、协作或调试（需结合具体业务代码路径验证）。

## 2. 依赖拓扑与耦合热点

### 2.1 Workspace 依赖

根 `package.json` 将 `@icw/helpers`、`@icw/schema`、`@icw/typing` 置于 dependencies，配合各 app 对 `@powercourse/*` workspace 引用，形成 **「平台核心包 + 产品线包」** 结构。评审关注点：

- **版本策略**：`semantic-release` + `semantic-release-monorepo` 表明倾向自动化发版；与 `standard-version` 并存时需明确哪条流水线为主，避免双轨版本号。
- **Peer / 重复打包**：Webpack 4 时代 tree-shaking 与 module federation 能力有限，多个 app 同构依赖可能造成 **vendor 重复**（需构建分析佐证）。

### 2.2 跨栈一致性风险

- **React Router**：编辑器使用 `react-router-dom@5`，cloud-driver 使用 v6，属于**同源异版**。短期可运行，长期增加共享组件与文档的心智成本。
- **Axios**：根与 `@icw/editor` 版本不一致，存在 **安全补丁与拦截器行为漂移** 风险。

## 3. 关键数据流

### 3.1 编辑 — 持久化

`realTimeSave` 中间件在 `main` model 的 action 派发后，若 `payload.pageId` 存在则调用 `savePageJson`。这是典型的 **「乐观本地状态 + 异步持久化触发」** 雏形；完整可靠性还需依赖 `savePageJson` 的去抖、冲突合并与失败重试（本仓库未在此文件中展开）。

### 3.2 导入 — 转码 — 通知

`importPPT` 云函数解析 body，区分 `PACK` / `DRAFT` 平台，调用不同 handler；成功路径对 PACK 平台回填 manifest 并 `notifyConversionResult`，失败路径标准化错误、可选 Lark 告警并再次通知。该链路体现 **异步作业状态机**：`ConversionStep` 驱动下游 UI。

### 3.3 播放 — SDK — 引擎

Player 通过 `player-sdk` 聚合 render/client/audio 等服务入口；渲染引擎包再封装 game-sdk 与 socket 客户端。分层上符合 **「播放器 shell → SDK 服务门面 → 引擎适配」**，有利于替换引擎或裁剪课堂能力。

## 4. 架构取舍结论

| 决策 | 收益 | 代价 |
|------|------|------|
| Monorepo | 契约统一、重构可原子提交 | CI 体量、缓存与受影响范围分析成本 |
| Rematch + Immer | 状态模板代码少、更新语义清晰 | 高级 Redux 生态工具需适配 |
| 独立渲染 app | 引擎升级与崩溃隔离 | 联调复杂度、发布矩阵膨胀 |
| SCF 转码 | 弹性算力、释放浏览器 | 冷启动、超时、本地调试与依赖打包体积 |

## 5. 架构评审待确认项（非臆测，列为验证清单）

1. `socket.io-client` 在引擎包中的连接鉴权、断线重连与版本兼容策略。
2. 课件 JSON 是否具备 **CRDT/OT** 或仅乐观锁；协作一致性等级。
3. `savePageJson` 与云端资源的 **幂等键** 与冲突解决策略。
4. SCF 单函数职责是否需按文件类型拆分为多个函数以控制 **权限最小化与包体**。
