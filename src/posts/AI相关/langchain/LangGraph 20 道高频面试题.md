# LangGraph 20道高频面试题（含标准答案，直接背）
## 基础概念篇
### 1. 什么是 LangGraph？
**答**：LangGraph 是 LangChain 生态下**有状态图编排框架**，专门用来构建多步骤、分支、循环、可中断、可回溯的 LLM Agent 和复杂工作流，弥补了传统 Chain 只能线性执行、无状态、不支持分支循环的短板。

### 2. LangGraph 和 普通 LangChain Chain 核心区别？
**答**：
- Chain：**线性、无状态、单向流转**，不支持分支、循环、断点续跑。
- LangGraph：**图结构、有状态**，支持分支判断、循环执行、状态持久化、中断恢复、时间回溯，适合复杂 Agent 业务。

### 3. LangGraph 四大核心要素是什么？
**答**：
`State 状态`、`Node 节点`、`Edge 边`、`Graph 图`。
执行逻辑：节点处理状态 → 更新状态 → 边根据状态驱动下一步流转。

### 4. 什么是 State？作用是什么？
**答**：State 是贯穿整个图的**全局共享数据模型**，所有节点统一读写；存放对话历史、用户输入、中间结果、业务参数等，是整个工作流的**流转核心**。

### 5. LangGraph 状态更新机制是什么？
**答**：采用**增量更新**，节点不直接修改原状态，只返回要更新的字段，框架自动合并到全局 State，保证状态不可变、可追溯。

## State 进阶篇
### 6. State 有哪两种定义方式？适用场景？
**答**：
- TypedDict：轻量、无类型校验，适合简单小流程、快速开发。
- Pydantic：带类型校验、默认值、嵌套结构、字段约束，适合企业级复杂业务。

### 7. 什么是 Reducer？作用是什么？
**答**：Reducer 是状态字段的**合并更新策略**，用来解决**多个节点同时修改同一个状态字段**的冲突问题。
常用：`operator.add` 列表追加、默认覆盖、自定义去重/排序聚合。

### 8. 为什么聊天记录要用 Annotated + operator.add？
**答**：保证每次节点返回的消息**追加到列表尾部**，而不是覆盖原有历史，实现多轮对话记忆累加。

## Node 节点篇
### 9. 什么是 Node？设计原则是什么？
**答**：Node 是 LangGraph **最小执行单元**，接收 State 输入，返回状态更新。
原则：**纯函数、无副作用、不操作外部变量、只靠返回值更新状态**。

### 10. Node 支持哪两种定义方式？
**答**：普通 Python 函数、可调用类（实现 `__call__` 方法）。

### 11. Node 缓存策略有什么用？
**答**：对相同输入的节点结果做缓存，避免重复调用 LLM、第三方工具，**减少耗时、降低 Token 成本**。

### 12. Node 异常重试机制适用什么场景？
**答**：网络不稳定、外部 API 调用、工具请求等易失败场景，自动重试提升工作流稳定性。

## Edge 流程控制篇
### 13. 普通边 和 条件边 区别与适用场景？
**答**：
- 普通边 `add_edge`：固定线性流转，A 执行完必走 B，适合固定流程。
- 条件边 `add_conditional_edges`：根据当前 State 动态路由，**实现分支、循环、判断逻辑**，适合 Agent 智能决策。

### 14. START 和 END 是什么？
**答**：LangGraph 内置常量，START 代表图的**起始入口**，END 代表**流程终止节点**。

### 15. Send 机制的作用？
**答**：用来实现**多节点并行执行**，在节点中返回 Send 对象，框架自动同时调度多个子节点，适合批量工具调用、并行任务处理。

## 企业级高级特性篇
### 16. 检查点 Checkpointer 作用？有哪些实现？
**答**：给工作流做**状态快照**，支持会话记忆、中断恢复、时间回溯、多会话持久化。
实现：内存 MemorySaver（开发调试）、SQLite（生产持久化）。

### 17. 什么是时间回溯 Time-Travel？
**答**：基于检查点，可以回到工作流**任意历史状态**，重新执行分支，用于复杂流程调试、线上问题复现、逻辑排查。

### 18. 子图的作用和优势？
**答**：可以把一个完整图当作节点嵌入父图，实现**模块化、分层解耦、代码复用**，适合拆分大型复杂工作流，易维护易扩展。

### 19. Command 对象相比普通返回有什么优势？
**答**：可以**同时更新状态 + 动态指定下一跳节点**，支持 goto 跳转、结合 Send 并行，比普通边更灵活，适合非常规复杂流转控制。

## 多智能体架构篇
### 20. 多智能体常见架构有哪几种？最常用的是？
**答**：三种：
1. 主管-工人（Supervisor-Worker）**最常用**
2. A2A 对等通信
3. 路由分发模式

主管-工人：主管拆解分配任务，工人执行子任务，主管统一汇总结果，结构简单、易落地、易维护。
