## 一、一句话定义（和你理解一致）
**Skill = 带元数据的结构化提示词目录**  
- 核心文件：`SKILL.md`（规则、流程、约束、示例）
- 可附带：配置、模板、小脚本、资源文件
- 作用：**只管“怎么思考/怎么做”，不管“直接执行代码”**
- 触发：匹配意图时自动把 `SKILL.md` 内容注入对话上下文

它就是你说的：**用来规范提示词、统一行为的模块**，不是 LangChain 那种可调用函数。

---

## 二、Skill 目录结构（极简但规范）
```
.claude/skills/your-skill/
├─ SKILL.md          # 核心：提示词/规则/流程（必选）
├─ frontmatter.yaml  # 元数据：触发词、优先级、是否自动加载
└─ resources/        # 可选：模板、示例、脚本、静态资源
```
- 无需代码，纯文本规则即可生效
- 支持 YAML 头信息控制触发方式（手动 `/skillname` 或自动）

## 三、核心能力：为什么它是“提示词规范神器”
### 1. 智能触发 + 渐进加载（省 Token）
- 初始只加载**名字+描述**（极省上下文）
- 对话匹配触发词（如“生成 SVG”“代码审查”）时，**动态注入完整 SKILL.md**
- 不相关时不加载，避免上下文膨胀

### 2. 强流程约束（解决“瞎做”问题）
`SKILL.md` 里写死**必须遵守的步骤/判断/输出格式**，例如：
```markdown
## 图形生成 Skill
### 规则
1. 先解析用户意图：图形类型、颜色、尺寸
2. 必须输出合法单标签 SVG，禁止嵌套
3. 参数缺失时：颜色=#000，尺寸=100
4. 输出格式：JSON { "svg": "...", "params": {...} }
```
Claude 会**严格按这个流程走**，不会乱发挥。

### 3. 可复用 + 可组合（提示词工程化）
- 一次写好，所有对话自动生效
- 多个 Skill 可叠加（如“图形生成 + 参数校验 + 错误处理”）
- 团队可共享 Skill，统一输出质量

### 4. 区分「能力」和「执行」（和你理解一致）
- Skill：**思考/流程/规范**（纯提示词）
- 工具（如 Bash/Read/Write）：**实际执行动作**
- 关系：Skill 指挥工具怎么用，工具负责干活

## 六、怎么用（极简三步，和你项目适配）
### 1. 新建 Skill
```bash
.claude/skills/svg-generator/
└─ SKILL.md  # 写好图形生成的规则、流程、输出格式
```

### 2. 写 SKILL.md（示例）
```markdown
name: svg-generator
description: 按用户自然语言生成合法单标签 SVG
trigger: ["生成", "svg", "图形"]

## 流程
1. 提取：类型（圆/矩形）、颜色、尺寸
2. 校验：参数合法，默认值兜底
3. 输出：JSON { "svg": "<circle ...>", "params": {...} }
```

### 3. 自动生效
对话说“生成蓝色圆形”→ 触发 `svg-generator`→ 注入规则→ Claude 按流程输出
