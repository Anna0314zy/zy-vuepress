这张图讲的是 **LangGraph 中 `stream` 方法的 5 种流模式**，它们决定了你的工作流在运行时，前端/客户端能收到什么样的实时数据。我帮你把每个模式的作用、适用场景和使用建议梳理清楚👇

---

## 一、模式核心对照表

| 模式 | 核心特点 | 典型场景 |
| :--- | :--- | :--- |
| `values` | 每一步结束后，返回**完整的当前状态快照** | 状态驱动型界面（如多轮对话的完整上下文、表单多步骤填写） |
| `updates` | 每一步结束后，只返回**状态中被修改的部分** | 只关心变化、想减少数据传输量的场景 |
| `messages` | 专门流式输出 LLM 的 Token + 元数据（调用节点、时间等） | 实时对话打字机效果、纯 LLM 响应流 |
| `custom` | 仅输出你在节点中用 `StreamWriter` 自定义的消息 | 进度提示、自定义事件通知（如“正在搜索资料…”） |
| `debug` | 输出所有细节（节点执行、状态、更新、事件） | 开发调试、排查流程问题 |

---

## 二、逐模式深度解读

### 1. `values`：全量状态流
- **工作原理**：工作流每执行完一个节点，就把整个 `state` 对象完整发送一次。
- **优缺点**：
  ✅ 前端处理最简单，直接用最新的状态覆盖即可，不用关心变化逻辑。
  ❌ 数据冗余，状态大的时候会增加带宽和前端渲染压力。
- **适用**：状态本身不大，或者你需要在前端完整重建整个流程状态（比如多步骤表单、复杂对话上下文）。

### 2. `updates`：增量更新流
- **工作原理**：只发送节点执行后对状态的“补丁”，比如 `{"topic": "冰淇淋和猫"}` 这种只包含变化字段的对象。
- **优缺点**：
  ✅ 数据量小，适合状态较大、变化频繁的场景。
  ❌ 前端需要自己维护完整状态，并合并增量更新。
- **适用**：需要优化性能、减少传输的生产环境。

### 3. `messages`：LLM Token 流
- **工作原理**：专门针对调用 LLM 的节点，实时返回 `(token, metadata)` 元组，让你能实现“打字机”效果。
- **特点**：只会输出 LLM 生成的内容，不包含状态的其他部分。
- **适用**：纯对话场景、AI 助手回复实时显示，是最常用的模式之一。

### 4. `custom`：自定义数据流
- **工作原理**：通过节点里的 `StreamWriter`，发送你自己定义的事件，比如进度、日志、自定义指令。
- **特点**：完全由你控制内容，不依赖状态或 LLM 输出。
- **适用**：需要给用户展示进度（如“步骤1/3：生成大纲…”）、发送前端交互指令（如“显示加载动画”）。

### 5. `debug`：全量调试流
- **工作原理**：输出流程中几乎所有事件，包括节点开始/结束、状态变更、异常等。
- **特点**：信息最全面，会暴露很多内部细节，不适合生产环境直接给用户看。
- **适用**：开发阶段排查问题，比如节点没执行、状态更新异常、流程分支错误。

## 三、组合使用技巧（超实用）
LangGraph 支持同时指定多个模式，比如：
```python
# 同时流式输出 LLM 内容 + 自定义进度消息
for mode, data in graph.stream(
    {"messages": [HumanMessage("讲个笑话")]},
    stream_mode=["messages", "custom"]
):
    if mode == "messages":
        # 处理打字机效果
        print(data[0].content, end="")
    elif mode == "custom":
        # 处理进度提示
        print(f"\n进度更新：{data}")
```
这样前端可以同时收到用户关心的内容（`messages`）和友好的进度提示（`custom`），体验会好很多。

## 四、怎么选？给你一个快速决策表
| 你的场景 | 推荐模式 |
| :--- | :--- |
| 纯对话，要打字机效果 | `messages` |
| 带状态的多步骤对话 | `values` 或 `updates` |
| 要给用户显示进度条/步骤提示 | `custom` + `messages` |
| 开发阶段，想知道流程跑没跑对 | `debug` |
| 生产环境，想省流量 | `updates` |

---

💡 小提示：这些模式和你做的编辑器项目也能结合起来，比如：

- 用 `messages` 模式流 AI 生成的文案
- 用 `updates` 模式同步画布状态的变化
